Objetivo central: que quienes prueban FitForm regresen, que quienes ya asisten mantengan su hábito y que quienes se alejan encuentren una razón para volver.
02 · Alternativas de fidelización

Cuatro formas de recompensar la constancia.

No hay un esquema cerrado. Podemos elegir una alternativa sencilla para el piloto y sumar otras según los resultados.

MODELO A

Recompensas por asistencia

Se reconoce a quien completa cierta cantidad de clases. Fácil de entender, comunicar y probar.

Ejemplo: al completar 4 u 8 clases, desbloquear un beneficio.

MODELO B

Puntos FitForm

Las asistencias y otras acciones elegidas suman puntos que pueden cambiarse por beneficios.

Ejemplo: acumular puntos para accesorios, experiencias o promociones.

MODELO C

Niveles de fidelidad

Reconocer la permanencia con categorías progresivas y ventajas exclusivas.

Ejemplo: Start, Active, Strong y Elite.

MODELO D

Retos de regreso

Ofrecer incentivos distintos según la etapa de cada persona: nueva, ocasional, constante o inactiva.

Ejemplo: un reto para completar la segunda visita o retomar la rutina.

Propuesta inicial: probar asistencia + retos de regreso. Después decidir si vale la pena añadir puntos y niveles. Los premios y las condiciones se definirían con FitForm, considerando su costo.
03 · Cómo funcionaría

Reservar como siempre. Recompensas adicionales.

El cliente seguiría utilizando la página y los widgets actuales de bsport. El programa de fidelización funcionaría como un complemento.

1 · ReservaLa persona reserva su clase como lo hace hoy.
→
2 · AsisteFitForm confirma la asistencia en bsport.
→
3 · Se registraEl programa actualiza su avance, según los datos disponibles.
→
4 · Se recompensaSe habilita un beneficio al cumplir la meta.

Para las personas que entrenan

Consultar metas, avances y beneficios desde una sección de FitForm en una etapa posterior.

Para el equipo FitForm

Un panel sencillo para ver participantes, metas cumplidas, recompensas pendientes y resultados.

Solo las asistencias confirmadas generarían avance; las reservas sin asistencia no contarían. El acceso de clientes al módulo de recompensas requeriría una identificación segura independiente o una opción oficialmente soportada por bsport.

04 · Dos caminos posibles

Podemos empezar con o sin conexión automática a bsport.

RUTA 1 · CON API

Conexión automática

Si bsport habilita el acceso y confirma que incluye los datos necesarios, ambos sistemas podrán intercambiar información sin descargar reportes manualmente.

  • Las asistencias se consultan de manera programada.
  • Los avances y recompensas se actualizan automáticamente.
  • El equipo dedica menos tiempo a administrar el programa.
  • Es la mejor opción para crecer a largo plazo.

POR CONFIRMAR

Permisos, datos de asistencia disponibles, costo, condiciones y frecuencia de actualización.

RUTA 2 · SIN API

Reportes y actualización controlada

Si no hay acceso a la API, podemos iniciar con reportes exportados desde bsport, siempre que contengan datos individuales suficientes.

  • El equipo descarga un reporte de asistencias.
  • Lo carga en el panel de FitForm Rewards.
  • El sistema calcula metas y recompensas.
  • El equipo valida y entrega los beneficios.

POR CONFIRMAR

Disponibilidad y calidad de reportes, identificadores y estados de asistencia. La actualización no sería inmediata.

Lo importante: ambas rutas usarían el mismo programa de recompensas. Si comenzamos con reportes, podríamos pasar después a una conexión automática sin rediseñar la experiencia completa.
05 · Qué utilizaríamos

Una solución propia, pequeña y complementaria.

Para no complicar la operación, proponemos conservar bsport y añadir solamente las piezas que faltan para administrar las recompensas.

YA EXISTE

bsport

Seguiría gestionando reservas, clases, membresías y registro de asistencia. No se reemplaza.

NUEVO

Sección visual de recompensas

Una experiencia en fitform.mx para mostrar metas, puntos y beneficios, cuando se decida abrirla a clientes.

Propuesta: React, adaptable al sitio actual.

NUEVO

Servicio de recompensas

El sistema que aplica las reglas, revisa avances y controla los canjes. También proporciona información al panel.

Propuesta: servicio propio en Node.js.

NUEVO

Registro seguro

Guarda el historial de puntos, metas, beneficios y entregas, evitando contar dos veces una misma asistencia.

Propuesta: base de datos PostgreSQL.

NUEVO

Panel del estudio

Permite consultar resultados, revisar recompensas y administrar el programa sin depender de un desarrollador para cada cambio.

SERVICIO DE ALOJAMIENTO

Infraestructura y cuidado

El programa viviría en un servidor o servicio en la nube, con acceso seguro, respaldos y mantenimiento.

Se puede evaluar VPS o alojamiento administrado según costos y operación.

Las herramientas indicadas son una propuesta tecnológica, no contrataciones realizadas. El alcance, presupuesto y proveedor de alojamiento se confirmarían después del piloto.

06 · Ruta de ejecución

Primero validar. Después automatizar.

1. Definir la recompensa

Elegir a quién queremos motivar, qué acción se premiará, cuál será el beneficio y cuánto puede costar.

2. Verificar los datos de bsport

Confirmar reportes individuales de asistencia y consultar oficialmente las condiciones de acceso a la API.

3. Lanzar un piloto controlado

Probar un modelo sencillo con un grupo definido, registro de avances y entrega supervisada de beneficios.

4. Medir resultados

Revisar segundas visitas, frecuencia, retención, canjes y costo del programa frente a una referencia comparable.

5. Automatizar y ampliar

Si funciona, conectar los datos de forma automática y habilitar la experiencia de recompensas en la web.

07 · Investigación: API de bsport

bsport sí anuncia una API pública. El acceso se solicita directamente a su equipo.

La página oficial de bsport explica que su API permite conectar información de clientes, reservas, suscripciones y pases con herramientas externas. También indica que revisan primero el caso de uso y después orientan al desarrollador para configurar el acceso.

Cómo solicitarla

  1. Contactar al responsable de cuenta de bsport o al equipo de soporte.
  2. Explicar que FitForm desea crear un programa de fidelización basado en asistencias confirmadas.
  3. Solicitar confirmación de los datos disponibles, documentación, permisos y condiciones comerciales.
  4. Una vez autorizada, realizar una prueba con datos de ejemplo antes del desarrollo.

Canales oficiales

bsport permite iniciar conversaciones desde el chat de su Back Office. También publica el correo support@bsport.io.

Su Centro de Ayuda describe además una ruta para consultar complementos: Ajustes → Suscripción → solicitar complemento. Esta ruta no confirma por sí misma que la API se active como complemento.

Estado real: la existencia de la API está confirmada por bsport; no está confirmado que la cuenta de FitForm tenga acceso habilitado, ni que la API incluya todos los estados individuales de asistencia necesarios para el programa. Tampoco se encontró una tarifa pública específica para este acceso.

Preguntas para bsport

¿La cuenta de FitForm puede acceder a la API? ¿Se requiere un plan o pago adicional? ¿Podemos consultar el identificador de cada cliente, su reservación y la asistencia efectivamente confirmada? ¿Hay límites de consulta, actualizaciones automáticas y documentación para desarrolladores? ¿Se pueden aplicar beneficios en bsport o deberán gestionarse manualmente?

PROPUESTA DE DECISIÓN

Empecemos con una prueba sencilla y medible.

Recomendamos validar recompensas por asistencia y retos de regreso, confirmar la disponibilidad de datos y ejecutar un piloto antes de invertir en un portal completo. La API de bsport sería el camino preferente para automatizar; los reportes permitirían comenzar si el acceso todavía no está disponible.

Decisiones que necesitamos de FitForm: tipo de incentivo, presupuesto de recompensas, participantes del piloto y autorización para consultar a bsport sobre el acceso a datos.
